# 理解校验指南

这份指南帮助用户检验自己对某段代码或方案的认识。它用于用户明确要求的测验或认知复盘；一般的解释、评审和修复按其本来意图完成。

## 把范围变成一个可回答的问题

先沿用用户给定的文件、功能、疑问或方案。只有无法合理判断目标时，才用一个简短问题确认范围。用户已经规定语言、难度、题数或批量作答时，直接遵从。

从当前材料中选择一个有用的理解点，例如某个配置为何生效、取消请求怎样到达工作任务、缓存键怎样区分两个调用。优先选择会影响用户判断的机制，不把冷僻语法或命名记忆当作默认题材。

默认一次讨论一个理解点。题目应足够独立，让用户知道要预测什么或解释哪一段行为。若相关依赖尚未读到，不把猜测包装成可判定的题目。

## 先有证据，再有题目

读取实际实现及回答本题必需的调用者、配置或契约，建立一条最小事实链：触发条件如何改变值或状态，最终产生什么可观察结果。记录相关文件、符号和关键分支；有帮助时附行号。

区分三个层次：

- **直接可见**：例如函数先检查取消标记，再写入队列。
- **由材料推断**：例如两个请求共享同一个缓存键，可能读到同一项内容；若缺少调用约束，就保留这一限定。
- **尚无依据**：例如外部服务如何处理已经发出的请求，当前仓库可能无法回答。

只用前两个层次能支撑的内容出题，并在必要处给出前提。方案没有实现时，以方案明确写下的规则为依据，不虚构函数、文件或运行结果。设计意图和实现行为不一致时，明确题目在问哪一层。

发现秘密或个人资料时不要将其写进题面与反馈。用不影响判断的占位符表示，引用最小必要内容。

## 没有指定文件时的阅读起点

先沿用用户正在讨论的功能。没有指定范围时使用随 Skill 分发的原生 `bin/pick-topic-<system>-<arch>`，其中系统为 darwin/linux/windows，架构为 amd64/arm64，Windows 追加 `.exe`；使用当前 Skill 的实际安装路径。

```text
/path/to/skill/bin/pick-topic-linux-amd64 /path/to/repo
/path/to/skill/bin/pick-topic-linux-amd64 /path/to/repo --exclude-path src/previous.go --seed 23
```

`--exclude-path` 可重复，支持文件或目录；把本会话已经选择过的路径逐个排除。`--seed` 让同一实现和同一候选集的选择可复现，不保证与其他工具使用相同的随机序列。成功输出一条仓库相对路径，普通使用不需要 Python 或 Go 运行环境。

Git 工作树按 Git 的 tracked/untracked 与忽略规则枚举；Git 不可用或当前目录不属于可读取工作树时，会静默改用有界目录遍历，此时不会解释项目自己的 `.gitignore`。文件筛选不是敏感数据检测，环境文件和密钥扩展名也可能通过。读取前应主动排除凭据、隐私资料和不相关秘密，不把正文或秘密放进题面。

选择结果只提供入口。读后若文件仅有常量或缺少上下文，可以沿一个明确的相关引用补读。若仍不足，最多再查看两个相关候选，然后说明缺少什么，请用户指定材料或选择已能证实的较小主题。不要为凑题无限扫描仓库，也不要反复随机直到碰到理想文件。

## 让回答显露推理

可按本题最合适的方式提问，无须轮流使用固定题型：

- **因果预测**：给定一个输入或事件顺序，问会产生什么结果，以及哪个条件决定结果。
- **机制解释**：让用户说明一项行为如何从入口传到结果，重点是关键连接，不要求逐行复述。
- **边界分析**：改变一个关键条件，问原先结论是否仍成立、从哪里开始不同。

题面写清必要前提，避免隐藏条件。默认只点明相关功能、机制或场景，先隐藏标准答案及其证据。不要附直接给出解法的代码摘录、源文件行号或暗示；用户要求提示、看代码或直接讲解时，再按请求提供。题目应考因果关系，不能靠隐去全部背景制造记忆题。

默认发出一个核心问题后等待用户回答，不在同一条回复中附上答案。用户要求批量时，一次给出其指定的题量并等待整体作答；用户要求直接看讲解时，切回解释，不强迫其继续答题。

## 回答之后如何反馈

先给出明确的正确或不正确结论，再按材料指出用户解释中的哪些关键部分成立。若存在偏差，定位到最早断开的因果连接：是漏了优先级、混淆了作用域，还是把一次检查误认为持续保证。给出简洁修正与证据，不只宣布对错。

例如：“你判断配置文件会被读取，这一点符合加载路径；不过环境变量在合并时后写入，所以这个键最终取环境变量。依据是 `loadSettings()` 中两次合并的顺序。”只有读到这一实现时，才可以使用这种表述。

回答可部分正确。把正确部分和未证实部分分别说明；对于存在多种合理解释的题目，承认题面限制并补齐前提。除非用户需要分数，不必制造精确的评分或掌握度百分比。

默认互动时，解答后询问是否继续；用户已要求连续练习时，在约定范围内继续，不逐题重复确认。下一问可选择本次偏差附近的一个新条件来验证修正是否被理解，但不重复刚问过的主题。已清楚说明的部分不必反复考；达到用户指定题数或用户要求结束时停止。

## 证据可能变化

用户质疑结论时先核对有关源文件、调用关系与前提，不把先前回答当作证据。代码或方案改动后，旧题的答案可能失效；重新读取受影响材料，再说明结论是否改变。

找不到必要实现、无法确认运行条件或证据互相冲突时，暂停该题的确定性评判，明确已知部分与缺口。可以改问一个证据充分的较小问题，但不能用猜测补齐标准答案。

## 校验与工程操作分开授权

读取代码以建立题目，不代表可以运行测试、启动服务、改动文件、写入数据库、提交代码或发布。若用户另有明确授权，按其原任务推进；不能从“考考我”推导这些权限。

当前对话可以保留一个简短的理解点记录，例如“已解释配置优先级；取消检查的时机仍有疑问”。默认不写文件、不写记忆、不形成长期能力标签。若用户要求保存复盘，再按指定内容和位置处理。

这类问答帮助发现当前认识中的偏差。源码阅读本身不证明系统正确，有限回答也不足以证明用户掌握全部实现。
