## 本轮研究取得了什么证据

文件选择器的行为研究对象是本机的一个 macOS arm64 可执行文件。研究先核对文件身份与 SHA-256，再用 REA 完成受控运行捕获，并在自建的小型目录中进行黑盒输入输出探测。

记录包含 1,081 次 subprocess 黑盒执行及 2 个 REA PTY 捕获场景。测试材料均为专门构造的 fixture；该黑盒阶段未读取第三方 Skill 指令或上游 Go 源码。受测目标是特定版本、系统和架构，不能代表其他版本或全部平台。

REA 的静态反编译引擎在本轮环境中未配置，因此本轮没有静态反编译结论。实际使用的是身份核对、运行捕获和输入输出观察，不能把这些证据描述为已恢复原实现。

行为合同覆盖以下用户可观察的能力：

- 从指定目录或当前目录选择一个候选文件。
- 使用 seed 在固定输入条件下复现本实现的选择。
- 重复排除文件或目录。
- 在 Git 工作树内利用 Git 的发现和忽略语义，并在 Git 不可用时回退遍历。
- 过滤部分依赖、构建产物和非文本候选，约束符号链接的范围。
- 对参数错误、坏目录和无候选给出失败结果。

这些观察用于形成独立实现的功能清单，而不是复制原工具的解析错误文字、随机序列或内部结构。本项目固定 seed 的可复现性针对自己的实现，不承诺同一个数值会选出与原工具相同的路径。

## 明确保留的边界

本轮观察证实原选择器可接受名称为 `.env`、`.pem`、`.key` 的普通测试文件；隐藏名称不构成统一的拒绝条件。因此不把这类文件筛选宣传为秘密扫描或隐私过滤。本项目的 Skill 要求代理在读取选中内容前判断敏感性，必要时排除或另选材料。

非 Git 目录、缺少 Git 或 Git 查询失败时，选择器静默使用本地遍历。该模式不保证项目忽略规则生效。根范围内有效文件的符号链接可能入选，指向范围外的链接不入选；这一约束不代表内容没有秘密。

文件大小、名称或文本探测只能缩小候选集合，不判断代码语义、题目质量或实现正确性。选择器只提供阅读起点；没有合适题材时，代理最多尝试三个候选起点，再明确说明材料不足。

研究没有证明所有文件名模式、随机均匀性、大型仓库性能或并发变化下的全部行为。REA 运行捕获也不等于完整系统调用审计。不能把有限观察扩展为全平台、全场景或百分之百的兼容声明。

## 独立实现与发布验证

新选择器以 Go 标准库独立编写，无第三方 Go 包，编译后不需要 Python 终端运行环境或 Go 开发工具链。构建目标为 macOS、Linux、Windows 各自的 amd64 与 arm64。构建目标、交叉编译成功和目标平台实机执行是不同状态，分别记录。

功能对照、独立设计差异以及实际构建和测试结果统一见 [COMPARISON.md](COMPARISON.md)。对照结论以列明的功能和证据为限，不宣称恢复了第三方的全部内部行为，也不把平台文件名当作已完成实机测试的证明。
