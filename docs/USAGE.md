# 使用指南

Praxis · 知行以静默协作为默认，理解校验按用户请求启动。Skill ID 为 `praxis`。

## 安装完整目录

将仓库中的 `skills/praxis` 整个目录放入宿主实际使用的技能目录。常见目录是 `~/.agents/skills/`；已有环境也可能使用 `~/.codex/skills/`。只复制这一份 Skill，无需安装整个仓库。

保留目录内的 `SKILL.md`、`references/`、`agents/`、`bin/`、`LICENSE`、`NOTICE` 和 `third_party/`。如果已有同名 Skill，先备份原目录和个人修改，再进行整体替换；零散覆盖可能留下旧版本文件。

全新安装示例，在仓库根目录执行：

```sh
mkdir -p "$HOME/.agents/skills"
cp -R skills/praxis "$HOME/.agents/skills/"
```

随后按宿主要求重新加载技能或开启新对话。Skill 支持隐式调用，也可在提示中显式写出 `$praxis`。

## 日常工作不必开启问答

例如：

> 用 $praxis 帮我完成这个修复，沿用刚才确认的范围。
>
> 解释这个配置加载函数为什么先读文件再读环境变量。
>
> 看看这份方案还缺哪些会影响决定的证据。

代理会复用共同已知，查明能够自行发现的事实，必要时询问只有用户知道的条件，并把关键未知缩成可验证的问题。它不会固定展示四个象限标题，也不会因为装了本 Skill 就让解释请求先经过测验。

理解校验以外的工程任务仍按自身授权推进。讨论一次实验不代表获准执行实验；说明一个修改也不代表获准提交或发布。

## 主动请求理解校验

给出你想检查的范围和形式即可：

> 考考我是否理解 src/config 的优先级，先一次一问。
>
> 我刚接手这个模块，请用边界案例检查我对任务取消的认识。
>
> 围绕这个缓存实现，用中文一次给我三道题，等我全部答完再反馈。
>
> 我想复盘刚才方案里的失败恢复过程，重点问因果关系。

指定文件、目录或机制时，代理直接读相关范围，不机械随机。没有指定范围时，代理可以先结合当前讨论定位，也可以调用原生选择器找阅读起点。

默认的问答节奏是：先有代码或方案证据，再提出一个核心问题；等用户回答后，说明哪些推理成立、偏差发生在哪里、什么证据支持修正。问题可以要求预测结果、解释一个机制或分析一个边界。用户指定批量、语言和题数时，这些要求覆盖默认节奏。

你可以随时要求直接讲解、换一个机制或结束。反馈不会因为一次答错给你贴能力标签；默认只在当前对话跟踪已讨论的理解点，不写长期记忆。

## 使用原生选择器

选择与你的系统和架构匹配的文件：

| 平台 | 文件 |
| --- | --- |
| macOS amd64 | `bin/pick-topic-darwin-amd64` |
| macOS arm64 | `bin/pick-topic-darwin-arm64` |
| Linux amd64 | `bin/pick-topic-linux-amd64` |
| Linux arm64 | `bin/pick-topic-linux-arm64` |
| Windows amd64 | `bin/pick-topic-windows-amd64.exe` |
| Windows arm64 | `bin/pick-topic-windows-arm64.exe` |

以下从仓库根目录运行；安装后的路径以实际 Skill 目录为准。编译好的工具不需要 Python 或 Go 开发工具链。

```sh
./skills/praxis/bin/pick-topic-darwin-arm64 path/to/repo --exclude-path private --exclude-path .env --seed 23
```

Windows PowerShell 示例：

```powershell
.\skills\praxis\bin\pick-topic-windows-amd64.exe path\to\repo --exclude-path private --exclude-path .env --seed 23
```

| 参数 | 含义 |
| --- | --- |
| `[REPO]` | 可省略的选择根目录；省略时使用当前目录。 |
| `--exclude-path PATH` | 排除一个文件或目录，可重复；路径需要属于选择范围。 |
| `--seed INT` | 为选择提供 seed；固定工具版本、候选集合和发现环境时可复现。 |
| `--help` | 显示当前工具的接口说明。 |

排除路径是具体路径，不是秘密匹配规则或 glob。示例中的 `.env` 排除选择根下的该文件，不会自动排除所有子目录里的同名文件。需要避免读取的目录和文件应明确排除。

成功时 stdout 只有一条相对于选择根的路径和换行，不包含正文。参数错误、无效目录或无候选会失败并提供诊断；不要把失败消息当作文件路径继续读取。工具本身不联网、不编辑仓库。

固定 seed 用于本实现内复现选择，不承诺匹配其他工具的随机序列。候选集合改变、Git 可用性变化或工具版本改变，都可能改变结果。

## Git、链接和敏感内容

在 Git 可用且目标属于工作树时，候选发现遵循 Git 语义：存在的已跟踪文件和未被忽略的未跟踪文件可以参与，已删除文件不会成为可读候选；已跟踪文件即使匹配忽略规则，仍可能参与。

非 Git 目录、缺少 Git 或 Git 查询失败时，工具静默退到本地遍历。项目忽略规则在这种模式下不保证生效，因此不要单靠 `.gitignore` 保护不应读取的材料。

根目录内有效文件的符号链接可能按链接路径入选；指向选择范围外的链接不入选。范围检查不能证明内容安全。

**选择器不是秘密扫描器。** `.env`、`.pem`、`.key` 以及其他隐藏或凭据名称仍可能入选。代理在读取选中内容前应判断敏感性，不适合时排除并另选。文件名没有明显风险也不表示正文没有秘密；阅读时仍应避免引用凭据、个人资料等非必要内容。

本地、不联网的描述仅指这个 CLI。后续代理对文件的读取和模型处理受宿主配置与权限约束，不应理解为整个协作过程全部留在本地。

## 找不到合适题材时

一个候选只是阅读起点。文件太零散、只有无关常量或缺少必要上下文时，可以有界补读关联材料，或排除该候选后换一个起点。无指定范围时最多尝试三个候选起点；仍无法形成可证实的问题，就说明缺少的材料，请用户指定范围或选择已有证据支持的较小主题。

不能为了凑题无限扫描，也不能因为选择器返回了一个路径就编造机制。方案没有实现时，只依据方案明确写出的规则，不虚构函数和运行结果。

## 反馈和工程操作的界限

用户质疑答案或材料发生变化时，重新核对相应证据。若无法确认运行条件、外部行为或关键依赖，明确已知部分和缺口，暂停确定性评判。

理解校验所需的只读查看，不自动授权运行测试、启动服务、改文件、执行迁移、提交代码或发布。已有独立授权的任务按原范围继续，本 Skill 不增加也不扩大权限。

有限问答只能帮助发现当前认识中的偏差，不能证明用户掌握整个系统，也不能保证代码正确。各平台构建与实际测试结果见 [COMPARISON.md](COMPARISON.md)，来源和许可见 [PROVENANCE.md](PROVENANCE.md)。
