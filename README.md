# Praxis · 知行

**Praxis** · Skill ID：`praxis`

让代理依据已知信息把工作推进到底，也让用户在需要时检验自己是否理解代码或方案。日常协作静默使用四类信息；理解校验由用户主动发起，围绕真实材料提问、等待回答，再用证据解释认识中的偏差。

[English](README.en.md) · [使用指南](docs/USAGE.md) · [来源与独立实现](docs/PROVENANCE.md) · [功能对照与验证](docs/COMPARISON.md)

## 能帮你做什么

| 能力 | 实际用法 |
| --- | --- |
| 复用共同已知 | 沿用已确认的目标、范围和决定，直接完成已授权工作，减少重复确认。 |
| 找准只有用户知道的事 | 只在个人偏好或现实约束会实质改变结果时提问。 |
| 主动发现可查事实 | 读取相关文件和实现，补充遗漏、纠正前提，说明证据与取舍。 |
| 缩小共同未知 | 把关键假设变成范围小、观察信号明确的验证问题；执行仍遵守原有授权。 |
| 按需校验理解 | 从真实代码或方案中选一个机制，让用户预测结果、解释原因或分析边界，再据回答反馈。 |

四象限是内部判断方式，不要求固定输出四个标题。简单请求保持简单；“解释这段代码”就直接解释，“修复这个问题”就推进修复，不要求用户先答题。

## 主要优点

- **少做重复澄清**：已确认的目标和决定继续沿用，只有会改变结果的问题才需要问。
- **理解有证据可回看**：围绕当前实现的机制和失败路径提问，回答后给出可核查依据。
- **工作与练习互不阻塞**：普通任务直接推进，需要检查理解时再切换到问答。
- **小而可审阅**：按需加载指南，本地原生工具只选择阅读起点，附源码与可复核产物摘要。

## 什么时候特别有用

- 委托代理开发后，想确认自己能说明关键行为和取舍。
- 接手一个模块，想检验对配置优先级、任务取消或缓存隔离的认识。
- 方案讨论中，想分清已证实的事实、合理推断和还缺证据的判断。
- 日常协作里，希望代理先自行查明上下文，少问已经确认过的问题。

理解校验默认一次提出一个核心问题，等你回答后再反馈。你可以指定语言、题数、难度或批量作答，也可以随时改为直接讲解。它帮助发现当前理解的缺口，不承诺掌握全部代码或保证学习效果。

可以这样使用：

> 用 $praxis 完成这个已确定范围的修改，并核验结果。
>
> 考考我是否理解这个模块的取消机制，先一问一答。
>
> 只围绕 src/cache，用中文一次给我三道题，我答完再反馈。
>
> 直接解释配置加载顺序，不用测验。

## 安装

项目仓库：[myflww/praxis](https://github.com/myflww/praxis)。

把 **`skills/praxis` 整个目录**复制到宿主的技能目录。常见位置是 `~/.agents/skills/`；已有环境也可能使用 `~/.codex/skills/`，以宿主实际配置为准。只需安装这一份 Skill，不必把整个仓库放入技能目录。

全新安装示例，在仓库根目录执行：

```sh
mkdir -p "$HOME/.agents/skills"
cp -R skills/praxis "$HOME/.agents/skills/"
```

已有同名 Skill 时，先保留备份与个人修改，再替换整个目录，避免把不同版本的文件混在一起。保留 Skill 内的 `LICENSE`、`NOTICE` 与 `third_party/`，不要只复制 `SKILL.md`。根据宿主要求重新加载技能或开启新对话。

## 原生阅读起点选择器

用户已经指定文件或功能时，代理直接读取相关范围。没有指定范围时，可用随附 CLI 选一个阅读起点；它不负责出题，也不判断文件是否值得考。最多尝试三个候选起点，材料仍不足就说明缺口，不无限扫描。

可执行文件位于 Skill 的 `bin/`：

| 系统 | amd64 | arm64 |
| --- | --- | --- |
| macOS | `pick-topic-darwin-amd64` | `pick-topic-darwin-arm64` |
| Linux | `pick-topic-linux-amd64` | `pick-topic-linux-arm64` |
| Windows | `pick-topic-windows-amd64.exe` | `pick-topic-windows-arm64.exe` |

这些是原生构建目标；已编译工具运行时不要求安装 Python 或 Go 开发工具链。各目标的实际构建、测试及差异记录见[功能对照与验证](docs/COMPARISON.md)，不把交叉编译视为所有平台均已实机验证。

接口为 `bin/pick-topic-{darwin,linux,windows}-{amd64,arm64}[.exe] [REPO]`，另支持重复的 `--exclude-path PATH` 与可复现选择的 `--seed INT`。省略 `REPO` 时使用当前目录。

```sh
./skills/praxis/bin/pick-topic-darwin-arm64 path/to/repo --exclude-path private --exclude-path .env --seed 23
```

选择器本身在本地运行、不联网；成功只输出一条相对路径，不输出文件正文，不编辑仓库。Git 可用且目标属于工作树时，采用 Git 的候选发现与忽略语义；非 Git 目录、缺少 Git 或 Git 查询失败时，静默退到本地遍历，此时不保证项目忽略规则生效。

**文件过滤不等于秘密过滤。** `.env`、`.pem`、`.key` 等名称的文件仍可能入选。代理读取选中内容前须判断敏感性并排除不适合的材料；已知敏感路径可显式排除。选择器允许根目录内有效文件的符号链接，拒绝指向选择范围外的链接。后续代理读源与模型处理遵循宿主配置，不属于 CLI 的本地运行保证。

## 证据和授权边界

出题前读取实际代码或用户提供的方案。回答后指出正确的因果链、偏差位置和支持修正的依据；证据不足不编标准答案。代码改动或用户质疑后重新查证，默认只在当前对话跟踪理解点，不写长期记忆。

“考考我”只授权理解校验所需的阅读，不自动授权运行测试、启动服务、改文件、提交或发布。源码阅读和有限问答也不能证明实现正确或已经全面掌握。
